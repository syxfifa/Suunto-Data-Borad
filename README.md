# Suunto Data Borad

Suunto Data Borad 是运行在 NAS、PVE 或 Linux 主机上的自托管运动看板。它通过官方 Suunto MCP 只读同步活动、睡眠、恢复、日常活动和保存路线，并把已读取的记录存入本地 SQLite。网页采用「冰川晨雾」主题，适配手机、平板和桌面。

当前版本 **V1.0.34** · 默认端口 **7383** · 时区 **北京时间（Asia/Shanghai）**

## 在 NAS 上部署

1. 在 NAS 的 Docker 管理界面创建一个 Compose 项目，选择项目目录。
2. 将仓库的 [docker-compose.yml](docker-compose.yml) 粘贴到项目配置，启动项目。Compose 会直接拉取 `jjsyx123/suunto-data-borad:latest`。
3. 在同一内网用浏览器打开 `http://NAS的IP:7383`。例如 NAS 的地址是 `192.168.1.20`，访问 `http://192.168.1.20:7383`。

如果用 SSH 部署，把 Compose 文件保存到 NAS 项目目录，在该目录执行：

```sh
docker compose pull app
docker compose up -d
docker compose ps
```

项目只运行一个 `app` 容器，容器名为 `suunto-data-borad`。配置中的 `7383:7383` 左侧是 NAS 对浏览器开放的端口。遇到端口冲突，可把左侧改为其他可用端口，访问地址随之调整。服务读取网页上保存的设置，无需准备 `.env`。

`./suunto-storage:/data` 把数据保存到 Compose 项目旁的 `suunto-storage` 文件夹。镜像会在启动时初始化权限，再以 UID/GID `10001:10001` 运行看板。请使用支持 Linux 文件所有权的本机可写目录。通过 NAS 防火墙把端口限制在可信内网。通过可信 HTTPS 访问时，可在 **设置 → 维护 → 访问控制** 设置密码，用户名是 `suunto`。

### 在内网通过 HTTP 使用访问密码

若只用可信内网的 HTTP 地址，可以在现有 Compose 的 `services.app` 下添加以下配置。HTTP 上的密码与看板流量会以明文传输。

```yaml
    environment:
      SUUNTO_ALLOW_HTTP_PASSWORD: "1"
```

重新部署容器后，用原 HTTP 地址打开 **设置 → 维护 → 访问控制**，设置密码并启用。之后浏览器登录框的用户名是 `suunto`。如移除该选项，已有密码继续生效，请改用 HTTPS 登录。

## 连接 Suunto

1. 在看板首页点 **连接 Suunto**，在同一浏览器内登录并同意授权。
2. 授权完成后，浏览器会返回看板的设置页，并自动开始同步。正常情况下可直接完成网页授权。
3. 在 **设置 → Suunto 连接与同步** 查看进度。首次同步通常从最近 28 天开始。活动入库后可点 **查看已同步活动**。

看板会在发起授权时自动注册 OAuth 客户端，并根据当前访问地址生成回调地址。用反向代理时，从准备长期使用的 HTTPS 地址进入看板，并将实际代理地址加入 `FORWARDED_ALLOW_IPS`，这样回调可使用正确的协议和主机。已有数据的实例重新授权时，请登录原 Suunto 账号。不同账号应使用独立项目目录和数据目录，并分别设置容器名和宿主机端口。

## 日常使用

| 页面 | 常用操作 |
| --- | --- |
| **概览** | 先看所选日期的昨夜睡眠、晨间身体资源和当日训练，再看本周训练。点活动名称直接查看详情，或进入 **睡眠与训练复盘**。返回首页时保留所选日期、汇总周期和图表或数据表视图。 |
| **训练趋势** | 按日或周查看距离、时长和活动次数。点图表日期可下钻到活动。切换周报或月报，周报可展开每周运动构成，并按项目查看相应活动。点 **查看进阶分析** 可查看 ACWR 等指标。 |
| **运动活动** | 用快捷日期、手工日期、运动类型和高级筛选查找活动。高级筛选支持名称或描述、最短距离、最短时长和最低 TSS。活动详情可查看 Suunto 返回的指标，也可直接对比近期同类活动。 |
| **运动对比** | 在活动列表勾选两条同类活动，或按名称和日期搜索后选 A、B。点 **交换 A/B** 可反转比较顺序。差值会显示每公里快多少秒、时长多多少分钟等方向。手机可从运动活动页进入。 |
| **睡眠与恢复** | 查看睡眠时长、身体资源和压力状态。**单日复盘** 把归到所选日期的睡眠、前一天训练和当天活动放在一起。HRV、静息心率等指标可在 **设置 → 目标与数据偏好** 绑定本地已采到的真实字段。 |
| **日常活动** | 按来源和日、周、月查看步数与千卡，也可以设置每日步数目标。周/月统计会标出有效天数。 |
| **保存路线** | 按名称、类型、距离或更新日期筛选。可预览 Suunto 提供的位置点并复制坐标。可以打开 OpenStreetMap，也可配置高德底图。 |

**快捷日期和常用视图。** 在训练趋势或运动活动页应用筛选后，点 **记住此视图**。直接打开该页时会恢复保存在当前浏览器的条件。运动活动页的「本周」「近 30 天」等快捷范围会随北京时间更新，手工输入的日期会按原样恢复。从周报等入口带来的日期和筛选条件优先。

**如何看待缺失数据。** 「已确认无活动」表示相应时段已查询且无记录。「同步未完成」表示该时段的覆盖仍有缺口，已有数字是本地小计。`—` 表示对应指标暂无值。页面找到匹配的失败窗口时，可以直接点到设置里的重试入口。图表加载失败时可以切换数据表。

## 同步、导出与备份

### 同步与历史补采

- **立即同步**。在 **设置 → Suunto 连接与同步** 手动触发并查看已处理、新增或更新的数量。自动同步默认每 30 分钟执行，可在 **同步频率** 调整。
- **补采历史**。在 **设置 → 历史补采** 选择近 90 天、近一年或自定义日期。补采可以暂停后继续。日常增量同步也会在可用时复核北京时间 7 天前和 28 天前的已覆盖记录。
- **处理失败窗口**。在 **同步详情与诊断 → 待修复的日期窗口** 查看出错日期、下次重试时间或重试单个窗口。Suunto 限流的等待期限会跨重启保留。

### 导出 CSV

在活动页点 **导出或分享当前筛选**，或者从 **设置 → 导出数据** 选择数据来源和日期。先点 **预览范围** 确认匹配条数。活动导出还可点 **查看匹配活动** 核对具体记录。日期范围包含结束当天，预览后的同步可能改变下载条数。

| 格式 | 适用场景 |
| --- | --- |
| 分享 CSV | 分享统计，保留日期和可用指标，省略名称、坐标、设备来源、记录编号和原始 JSON。 |
| 完整分列 CSV | 用表格软件分析，包含记录编号、名称、完整时间和指标列。距离单位为公里，时长单位为分钟。 |
| 原始 CSV | 个人存档，包含原始 Suunto JSON，可能含健康数据、名称与坐标。 |

### 备份与恢复

在 NAS 的 Compose 项目目录执行以下命令。默认 ZIP 包含数据库和已有的 `config.json`。如确需包含 Suunto 令牌，可在 `backup` 后加 `--include-token`。ZIP 应保存在私有目录。

```sh
umask 077
archive="$HOME/suunto-backup-$(date +%F-%H%M%S).zip"
docker compose exec -T --user 10001:10001 app python -m suunto backup > "$archive"
docker compose exec -T --user 10001:10001 app python -m suunto verify --record < "$archive"
docker compose exec -T --user 10001:10001 app python -m suunto drill --record < "$archive"
```

每步成功后再继续。**设置 → 维护 → 备份与恢复** 会显示归档生成时间、验证时间和镜像版本，并核对验证与演练是否使用同一个 ZIP。如果归档生成后又完成过完整同步，页面会提醒更新前考虑重新备份。演练在临时目录恢复数据库和已有设置，看板可以继续运行。若旧状态没有归档指纹，可用同一份 ZIP 重新执行上面两条带 `--record` 的命令。

实际恢复会替换本地数据。请先备份现有数据并确认归档属于同一 Suunto 账号。令 `archive` 指向已验证的 ZIP，在正确的项目目录停止服务后执行：

```sh
docker compose stop app
docker compose run --rm --no-deps -T app python -m suunto restore --component database --replace --same-account < "$archive"
docker compose run --rm --no-deps -T app python -m suunto restore --component settings --replace < "$archive"
docker compose up -d
```

如果归档未包含设置文件，只恢复数据库即可。恢复到空目录后，按需重新连接原 Suunto 账号、设置访问密码和填写高德凭据。可在 NAS 任务计划里定期运行备份和验证命令，归档建议放在独立存储位置。

## 可选的高德地图

1. 在高德开放平台创建应用，添加 **Web 端（JS API）** Key，复制 Key 和安全密钥。若设置了域名白名单，请填写浏览器实际访问看板所用的域名。[高德申请步骤](https://lbs.amap.com/api/javascript-api-v2/prerequisites)
2. 打开 **设置 → 高德地图预览**，填写 Key 和安全密钥，选择 Suunto 路线的坐标系。建议用已知地标核对 WGS84 或 GCJ-02，勾选 **自动显示高德地图** 并保存，然后点 **测试连接**。
3. 在 **保存路线** 查看标记。开启自动预览后，页面会加载首条有位置点的路线，并将显示位置发送给高德。高德代理每分钟最多转发 30 次请求。地图暂时无法加载时仍可查看和复制坐标。[高德安全密钥说明](https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode)

## 更新与排查

已有部署在原 Compose 项目目录更新，保留 `./suunto-storage`：

```sh
docker compose pull app
docker compose up -d
```

在 **设置 → 维护** 核对版本。想固定版本，可把 Compose 的 `image` 改为 `jjsyx123/suunto-data-borad:1.0.34` 后再执行更新命令。旧部署若使用命名卷或其他挂载路径，先从原部署备份，再在新目录恢复。旧的双服务版切换为单服务后，可在确认当前 Compose 项目时使用 `docker compose up -d --remove-orphans` 清理旧的初始化容器。回滚到 V1.0.15 或更早版本时，请用目标旧版镜像恢复升级前的归档，再启动应用。

| 现象 | 怎么排查 |
| --- | --- |
| 浏览器打不开 | 执行 `docker compose ps` 和 `docker compose logs --tail 100 app`，检查 NAS 防火墙、端口和容器名是否被占用。 |
| 日志提示数据目录权限错误 | 确认 `suunto-storage` 是 NAS 的本机可写目录，文件系统支持 Linux 所有权设置。部分网络共享会拒绝修改所有者。 |
| 授权后回不到看板 | 在准备使用的看板地址重新发起授权，保持同一浏览器和访问地址。若使用反代，核对 HTTPS、代理转发信息和 `FORWARDED_ALLOW_IPS`。 |
| 密码框和按钮呈灰色 | 内网 HTTP 可按上文显式开启密码登录。使用 HTTPS 时，从可信 HTTPS 地址进入 **设置 → 维护 → 访问控制**。如果浏览器已显示 HTTPS，核对反代是否发送 `X-Forwarded-Proto: https`，以及 `FORWARDED_ALLOW_IPS` 是否包含看板实际看到的代理 IP。 |
| 同步限流或部分日期缺失 | 在 **设置 → 同步详情与诊断** 核对来源覆盖和下次可重试时间。历史缺口可选对应日期补采。 |
| 看不到路线位置或某项健康指标 | 先查看页面的数据状态。无路线位置点时无法预览该路线位置。健康指标以 Suunto MCP 实际返回的字段为准。 |

**数据目录。** `suunto-storage` 中的 `suunto.sqlite` 保存同步记录和进度，`config.json` 保存网页偏好，`token.json` 保存 Suunto 授权，`amap.json` 保存高德设置，`access.json` 保存访问密码哈希。数据目录已从 Git 和镜像构建上下文排除。

**开发与发布。** 应用使用 FastAPI、Jinja2、Chart.js 和 SQLite。GitHub Actions 为 NAS 常见的 AMD64 和 ARM64 架构构建镜像，运行测试、Compose 启动与升级验证并扫描镜像。发布成功后，版本号、提交短 SHA 和 `latest` 指向同一镜像摘要。[GitHub Actions](https://github.com/syxfifa/Suunto-Data-Borad/actions)
